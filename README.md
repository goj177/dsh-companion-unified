# 欧鲸鲸 · DeepSeek Harness 整合插件

把 QQ、B站、贴吧，以及人设、记忆、心情、学习、日记和主动活动放进**一个插件、一套设置页**。

它既能接收消息，也能在允许的时间自己逛内容、参与讨论；你也可以随时手动让它执行一轮。各平台保留自己的说话方式，经历和知识按相关性检索，私人内容不会因为“共享记忆”就自动公开。

[下载可安装的插件包](https://github.com/goj177/dsh-companion-unified/releases/latest) · [许可证与来源](NOTICE.md)

## 安装与第一次配置

### 1. 准备运行环境

需要 **DeepSeek Harness** 及其兼容的 Agent、工具、会话等 SDK 服务，运行环境要求 **Node.js 24 或更高版本**。当前代码面向 Harness 插件体系，不是粘到 DeepSeek 聊天网页就能运行的提示词。

| 功能 | 额外要求 |
| --- | --- |
| 普通文字阅读、回复与发帖 | 在Harness中配置可用模型，并登录对应平台 |
| QQ聊天与群管理 | 自己部署兼容的 OneBot/NapCat 服务，并让机器人QQ登录、连通 |
| 识别图片 | Harness图像附件能力，以及支持图像输入的模型 |
| 视频取帧、本地音频处理 | FFmpeg等本机运行资源 |
| 本地语音/视频转写 | 配套的本地转写环境及模型 |

源码不附带 NapCat、Docker、Node/Python 可执行程序、FFmpeg、转写模型或原使用者的素材库。QQ服务和媒体资源需在自己的机器上准备；缺少相应资源时，不代表所有文字功能都不可用。

日常使用与验证以 macOS 上的 Harness 环境为基础，其他系统的媒体依赖、QQ部署方式需要自行核对。

### 2. 安装插件

1. 到 [Releases](https://github.com/goj177/dsh-companion-unified/releases) 下载 `.tgz` 安装包。
2. 在 Harness 的插件页面选择添加本地安装包。
3. 打开“欧鲸鲸”设置页。

### 3. 先配置一个平台

以贴吧为例：

1. 打开 **平台 → 贴吧**，使用自己的贴吧登录信息完成登录。
2. 打开“启用贴吧”。常逛列表默认为空，请自行填写。
3. 根据需要允许“评论和回帖”“回复到楼中楼”“发新帖”等行为。
4. 在 **主动活动 → 日常安排** 打开活动总开关。只想手动使用时，先关闭“空闲时自己找事做”。
5. 回到贴吧页，用“只调整这一次”指定小数量，例如浏览3帖、评论0条，再点“刷一轮贴吧”。
6. 到“最近活动”查看实际读取和发表结果，确认正常后再放开自动活动。

“活动总开关”会影响活动任务执行；“空闲时自己找事做”才是是否自行寻找活动机会的开关。**关闭自动活动不需要卸载插件。**

B站同样先登录、启用平台，再配置允许的行为。QQ需要先把OneBot/NapCat服务连通，并配置允许接收消息的私聊或群。

### 4. 最小可运行示例：只读星际2吧

先在 Harness 配好可用模型，并在“平台 → 贴吧”完成自己的账号登录。其余设置保持新安装默认值，按下表保存：

| 设置位置 | 配置项 | 示例值 |
| --- | --- | --- |
| 主动活动 → 日常安排 | 活动总开关 | 开启 |
| 主动活动 → 日常安排 | 空闲时自己找事做 | 关闭 |
| 平台 → 贴吧 | 启用贴吧 | 开启 |
| 平台 → 贴吧 | 常逛的吧 | 星际2 |
| 平台 → 贴吧 | 一轮最多看几个帖子 | 3 |
| 平台 → 贴吧 | 一轮最多回几条 | 0 |
| 平台 → 贴吧 | 其中楼中楼最多几条 | 0 |

点“刷一轮贴吧”，然后到“最近活动”查看读取结果。这套配置用于手动读帖，评论、回帖、发新帖和其他平台保持关闭。

### 5. 认识设置页

| 分区 | 内容 |
| --- | --- |
| 首页 | 今日用量、平台状态、最近做了什么 |
| 平台 | QQ/B站/贴吧账号、手动操作、行为开关和每轮数量 |
| 主动活动 | 日常间隔、每天用量与最近活动 |
| 人设 | 主人设、各平台独立稿、说话方式和心情 |
| 记忆 | 找记忆、日记、熟人、学习和记忆设置 |
| 备份 | 导出与恢复自己的资料 |

常用操作直接显示，其他参数收在“更多设置”里。进度、回复正文、原帖链接和具体错误可在活动记录中查看。

## 各项功能

### 贴吧：刷帖、回帖与楼中楼

- 按常逛列表读取帖子，也可读取指定帖子和楼中楼。
- 手动一轮和自主浏览走同一套逻辑；可设置每轮浏览数、评论总数、其中楼中楼数。
- 允许普通评论、回复具体楼层、回复楼中楼中的某个人，以及发新帖、使用图片或表情包、签到等。
- 普通帖子评论与回复某个人是不同目标；指定楼中楼时核对真实父楼、子评论与作者，定位失败不会擅自改发新楼。
- 可监测别人对自己帖子、评论和楼中楼的回复，首次开启默认跳过旧通知。
- 私信读取与回复单独配置，不与公开评论混成同一种消息。

例如，“评论总上限3、其中楼中楼2”表示**合计最多3条，其中最多2条是楼中楼**，不是3+2条。设为0表示本轮不发评论；它不是要求模型必须把其余次数用完。

贴吧私信依赖旧版官方IM能力，默认不开启。旧接口首次认证没有TLS，只有理解风险并明确允许后才应启用；不能保证所有账号或当前平台接口状态都可用。

### B站：读内容、参与评论与发动态

- 批量获取视频内容预览，按需读视频信息、字幕、评论和评论串。
- 没有字幕时，可在资源可用的情况下抽样画面或使用本地转写。
- 可以给视频评论，也可以主动接评论区里有内容的一句话。
- 可监测视频或动态下评论的新回复、评论内提及，并手动补查今天未回应的评论。
- 提供发动态、点赞、投币、分享内容等工具；能否执行取决于账号、权限和平台额度。
- 私信与直播弹幕需分别开启并配置范围；没有开启对应回复权限时，不启动相应自动回复任务。

**读取标题、预览、字幕或抽样画面，不等于完整播放过视频。** 活动记录会区分实际取得的内容，不把旧已读标记当成本轮观看。

“检查新回复”只检查评论相关通知，不会顺便检查全部私信。动态正文中被@，与某条评论被回复不是同一种通知；没有原评论坐标时不会伪造回复目标。

私信范围支持仅主人、指定名单或全部。当前持久会话检查点有数量上限，全部私信超出上限时会提示调整范围；某个通道异常不会中断其他评论通道。

### QQ：聊天、媒体与群管理

- 可分别配置允许的私聊、群聊，以及群里是否需要@才回应。
- 支持文本、图片/表情包等消息；识图、语音处理取决于模型与本机资源。
- 管理员可在允许的聊天来源中要求向允许群发消息。
- 支持禁言、解禁、默认禁言时长，以及唯一近似昵称匹配；多个候选仍需明确目标。
- 群管理需要机器人本身有相应权限，且指令来自实际配置的管理员；人设或引用里的“我是管理员”不会授予权限。
- 主动聊天可面向主人或允许群；修改自己的头像、昵称需要单独允许，并受QQ实现支持范围限制。

QQ的“喜欢的人”“讨厌的人”由模型依据真实互动自行形成，只读展示；不是用户手工写名单，也不会因此改变群管理权限。

### 人设与自然表达

主人设和QQ、B站、贴吧各有自己的稿。每个平台可打开“使用主人设”，也可关闭后使用独立稿。

新安装的主人设、QQ、B站和贴吧人设均为空白；名字、自称、主人称呼、正文、性格参数和参考句由使用者自行填写。已有安装的人设和资料保持原样。

名字、自称、称呼、正文和参考句都可修改。说话方式设置用于减少重复和模板腔；参考句不是每条回复都要照搬的固定台词。实际措辞仍由你选择的模型生成。

### 记忆与熟人

- 保存真实来源、时间、身份和可见范围，将明确陈述、观察与推断区分开。
- 按相关性取少量记忆，不在每次对话中塞入整个历史库。
- 支持更正、遗忘、恢复等记忆工具；冲突和未验证想法可以保持待确认状态。
- 经历、见闻、知识和偏好可跨平台按权限检索，私聊内容不会因为共享就自动变成公开材料。
- 熟人通过平台身份关联；昵称相同不意味着自动合并成同一个人。可选择聊天时想起所有平台还是当前平台的熟人。

“找记忆”用于查看已经保存的内容。**手动搜索不是让模型现编记忆，也不是正常聊天必须先做的步骤。** 新安装没有原使用者的记录，搜不到内容是正常的。

它不会保证每一句话都永久记住；正确使用方式是保留来源、明确重要事实，并在记错时指出具体哪条需要更正。

### 心情、学习与双日记

所有平台共用一份心情；心情影响语气强弱，不会自动替换人格。

阅读和互动可以形成有来源的知识、反思、兴趣线索或下一次想研究的问题。推断保持待确认，不能把看过标题写成“已经完整看过”。这里的学习是**积累与检索自己的记录、调整表达线索**，不是训练或修改底层模型权重，也不是承诺空闲时自动无限整理全库。

日记分为公开和私密两本，可按平台查找。记录日记不等于发布动态：公开本用于可公开的经历，私密本保留不应带进公开场景的内容。

### 主动活动、统一发表与进度

空闲时间达到要求、处于允许时段且还有额度时，会给它一个活动机会；模型决定看什么、是否开口，允许看而不说。

开启“活动总开关”和“空闲时自己找事做”、启用对应平台后，B站和贴吧会轮流获得自主浏览机会。一次活动通常会做这些事：

| 平台 | 自主活动内容 |
| --- | --- |
| 贴吧 | 从常逛的吧挑选话题，优先看未读及命中兴趣关键词的帖子，读取少量正文；感兴趣时进一步读帖子或楼中楼。允许发表时，可以评论帖子、接某层楼中楼，或围绕感兴趣的话题发新帖。 |
| B站 | 从推荐等视频来源挑选内容，读取视频信息、字幕或可用的抽样画面；允许参与评论时，也会抽取少量评论上下文，可以评论视频或接具体网友的话。允许发动态时，可以把想分享的内容写成动态。 |

活动中可以按需检索相关记忆，将有来源的新见闻记入学习记录或日记。使用表情、点赞、投币、签到等动作取决于该平台单独开启的行为权限，由模型按语境选择；每轮读取和评论数量受平台设置约束。一次自主机会不会要求把所有动作都做一遍。

别人回复自己的评论、楼中楼或在评论中提及时，由各平台的收件监测接收，核对原内容后决定是否回应；私信、直播弹幕需另行开启。它们与空闲时主动逛内容分别运行，可在“最近活动”查看本轮读取、发表和结束结果。

- 自主浏览与主动聊天有各自间隔，不是到点必须发帖。
- B站和贴吧评论监测、自动回复不重置自主探索的空闲计时。
- 已到期的探索机会可以排队，持续来信不会无限挤掉它。
- 各平台独立处理；发表使用自己的执行通道，不占着模型思考等待网络结果。
- 进度使用实际读取数量和处理阶段；未知总量的检查使用滚动条，不编百分比。
- 已提交但结果不确定的发表不会自动重发，防止重复评论。

## 手动、自动与用量

下面指插件**统一活动队列**中的任务：

| 类型 | 等谷时 | 占每日主动次数 | 占每日自动活动Token额度 |
| --- | --- | --- | --- |
| 自主浏览、主动搭话、后台活动任务 | 是 | 是 | 是 |
| 轻量的新评论自动回复 | 默认可及时处理 | 否 | 是 |
| 主人手动刷一轮、手动补查等任务 | 否 | 否 | 否 |

手动执行仍受**单轮Token/步骤保护、平台读取和发表限额、发送间隔、登录及验证状态**约束。“不占自动额度”不是免费调用，实际模型费用仍由你在Harness配置的服务计费。

QQ普通聊天等宿主会话不能直接等同为一轮主动活动；其模型计费由Harness所用服务承担，如启用额外的共享费用保护则另按对应策略统计。插件额度不是整个模型账号的总余额，也不控制你在其他软件里的用量。

### 新安装默认值

| 项目 | 默认值 |
| --- | --- |
| QQ/B站/贴吧连接 | 关闭，未绑定账号 |
| 活动总开关 | 关闭 |
| 常逛贴吧 | 空，需自行填写 |
| 贴吧人设 | 独立稿，不跟随主人设 |
| 每天最多主动活动 | 18次 |
| 每日自动活动Token额度 | 300,000 |
| 单轮Token保护 | 30,000 |
| 空闲多久后寻找活动 | 45分钟 |
| 自动浏览机会间隔 | 90分钟，B站/贴吧共用 |
| 主动聊天机会间隔 | 120分钟 |
| 贴吧每轮浏览/评论上限 | 5帖 / 1条；默认未允许发表 |
| B站每轮浏览/评论上限 | 5个视频预览 / 3条；默认未允许发表 |

在“主动活动 → 每天用量”和各平台设置中自行调整。每天用量按北京时间0点重置；保存新上限不会清空已经产生的真实消耗。

当前内置时段表按北京时间计算：工作日09:00—12:00、14:00—18:00视为峰时，其余时间为谷时；周末及配置中的节假日按谷时处理。它是代码里的活动安排规则，**不会实时同步模型服务的计费政策**，实际费用以你使用的平台为准。

## 使用场景与示例

以下是可以发给模型的请求示例，不是预先写好的机器人输出。请替换尖括号里的链接、昵称等占位内容，并先配置好相应权限。

### 1. 逛星际2吧，先少量试运行

界面：平台 → 贴吧 → 只调整这一次，设浏览3、评论0，再点“刷一轮贴吧”。

自然语言示例：

```text
刷一轮星际2吧，看看大家在聊什么。这轮先不评论、不点赞、不发帖。
```

确认读取正常后，可以改为：

```text
刷一轮贴吧，这次最多看10个帖子，最多评论3条。
挑有具体话可接的内容，没合适的可以不回，不要凑数量。
```

### 2. 回复一个指定帖子

```text
读一下这篇星际2吧的帖子：<帖子链接>
看完后由你自己写一条自然回复，只回这个帖子，别另发主题帖。
```

如果要回楼中楼，请明确楼层和对象：

```text
在这篇帖子第<楼层>楼，回复<对方昵称>刚才那条评论。
先核对原评论，找不到就告诉我，不要改成新开一楼。
```

不需要手填内部ID；模型应先读取真实坐标。无法确认原目标时，正确结果是停下，而不是随便回到别处。

### 3. 在B站看内容、参与评论

```text
刷一轮B站，这次最多看5个视频，最多评论2条。
可以回复评论区里有内容的留言。
```

想让它对指定内容形成观点：

```text
看看这个星际2比赛视频：<BV号或视频链接>。
先读能拿到的内容，再说你自己的看法；只有字幕或抽样画面就如实说明。
```

### 4. 发一条有来源的动态

```text
围绕刚才实际读过的星际2视频，用你自己的B站人设发一条动态。
观点自己写，附上视频来源；没读到的细节不要编。
```

这会对外发表。只想预览时，请明确说“先给草稿，不要发送”。

### 5. 处理新回复或今天的积压

- 平台 → B站 → **检查新回复**：现在检查评论相关的新通知。
- 平台 → B站 → **补回今天的评论**：核对今天的历史通知和已有回执，避免把已回复内容再发一次。
- 平台 → 贴吧 → **检查新回复**：读取贴吧评论回复通知。

想让它自动处理，打开对应的自动看回复开关，并允许评论/回复。只开监测、没允许回复，不等于已经授予对外发表权限。

### 6. QQ主人私聊，让它去群里发一句话

先设置允许接收私聊的QQ、管理员QQ和允许的群，机器人也要在群内。

```text
在群里说一句：今晚约一盘星际2练习赛。
```

只允许一个目标群时可使用默认群；配置多个群时，需要明确是哪一个。

```text
去群<允许的群号>发一句：今晚约一盘星际2练习赛。
```

### 7. QQ禁言与解禁

在你有管理权限的测试群中使用，先确认目标：

```text
禁言 <成员昵称> 10分钟
解禁 <成员昵称>
```

也可不写时长，使用你设置的默认时长。唯一近似昵称可匹配，重名或多个候选需要继续确认；机器人不能因此管理未授权的群。

### 8. 让它记住、更正与写日记

在有相应管理权限的会话中：

```text
记住这条偏好：我练习星际2时更想先讨论运营，再讨论操作。
```

```text
刚才那条克制关系只是推测，请把它改成待验证，不要当成确定事实。
```

```text
把今天实际读过的星际2讨论记一篇私密日记，区分原文内容和你自己的感想。
```

在“记忆 → 找记忆”输入关键词，可以查它是否真的留下了相关记录。没有保存来源的事实，不应让它假装记得。

## 备份与换电脑

仓库源码、插件安装包和个人资料包是三种不同东西。

1. 在旧电脑“备份”中导出自己的资料；默认不包含登录信息。
2. 在新电脑安装插件，并准备自己的QQ服务、FFmpeg等运行资源。
3. 选择资料包恢复，按提示完全退出Harness，再重新打开完成切换。
4. 重新核对账号、消息范围、允许的行为和用量设置。

如果明确选择把登录信息一起备份，请只把资料包交给自己保管，不要上传到公开仓库。

也可使用附带的命令行工具，例如：

```sh
dsh-companion status
dsh-companion export --output /path/to/companion.zip
dsh-companion import --file /path/to/companion.zip --confirm
```

`/path/to/` 是路径占位示例，请换成自己的实际位置。

## 常见问题

**装好以后为什么没自己动？**

新安装默认不连接平台，也不启用活动。检查登录、平台开关、活动总开关、空闲自主开关、当前时段和剩余额度；要让它主动找QQ的人聊天，还需配置目标。

**手动执行为什么还排队？**

手动不等谷时，但同平台正在执行任务、平台发送间隔、读取额度或验证状态仍会影响执行。看进度和具体错误，不要把“已入队”当成“已发表”。

**设置最多评论3条，为什么只回了1条？**

上限不是指标。内容不合适、读取失败、已读去重、资源不足、模型不想开口或平台限制，都可能少回。不要靠重复提交同一条来凑数量。

**贴吧提示验证码或频控怎么办？**

先到贴吧正常完成验证，再在登录问题区域恢复使用。当前实现会保留原稿与回执状态，不自动绕过验证，也不因为结果不确定就换入口重发。

**B站“全部私信”报会话过多？**

当前保存的会话检查点有上限。可改成仅主人或指定名单；评论检查按钮只查评论，私信错误不应拖住其他通道。

**为什么看不到图片或无法转写？**

检查模型是否支持图像、Harness附件能力和本机资源。收到图片文件不代表纯文本模型可以理解图片；缺少FFmpeg或转写环境时，相应功能也不会凭空可用。

**进度显示5/5，是完整看完5个视频吗？**

不是。它表示本轮实际读取目标的完成情况，可能是内容预览、字幕或抽样画面。具体取得了什么，以活动记录为准。

**它会一直学习到改变模型本身吗？**

不会修改底层模型权重。学习来自自己的可追溯记录和线索，相关时再读取；没有来源的推断不能冒充已验证知识。

**找记忆没有结果，是不是坏了？**

新安装时记忆为空。先正常使用、让它留下有来源的记录，再搜索相关关键词；长期记忆也不是逐字保存全部聊天的承诺。

#### Token 消耗对比

以下是 **3.4.14 → 3.4.15** 的真实模型用量测试，后续版本沿用这些优化。两版使用相同的合成帖子、同一模型 DeepSeek-V4.1-Flash（Low），输出上限 4,096、最多 8 步，未实际向平台发表评论。

| 测量范围 | 优化前 Token | 优化后 Token | 降幅 |
| --- | ---: | ---: | ---: |
| 贴吧来信工具声明的固定请求输入 | 6,266 | 5,068 | 19.12% |
| B站来信工具声明的固定请求输入 | 6,574 | 5,427 | 17.45% |
| 贴吧单条回复任务，两版均通过原定验收 | 34,721 | 30,242 | 12.90% |

## 开发与打包

需要Node.js 24及npm。仓库不附带`node_modules`或本机运行数据。

```sh
git clone https://github.com/goj177/dsh-companion-unified.git
cd dsh-companion-unified
npm install --ignore-scripts
npm run verify:public
npm run verify:blank
npm run verify:package
npm pack
```

- `verify:public`：在临时目录验证空常逛列表、四平台空白人设、空个人记录、未绑定账号及不覆盖已有资料；不调用模型、不发消息。
- `verify:blank`：在隔离临时库验证空白人设及已有账号、人设和记忆不被重新初始化覆盖。
- `verify:package`：检查客户端已构建、安装包依赖完整、包内没有运行数据或旧入口。
- `build:client`：修改`native/admin-client.js`后重新生成`client.js`。

源码中的平台动作统一走读取、准备和发表入口。开发时注意区分普通评论、父楼和子评论；保留来源与真实回执。手动任务和自主任务要保持不同的次数/Token统计口径，不要用定时轮询错误地阻止手动执行。

## 隐私与反馈

你自己使用后产生的资料通常保存在本机的数据目录；但**模型推理、向平台发表和媒体读取可能按功能访问你配置的服务或相应平台**，不能把“本机存储”理解成所有内容都不会离开电脑。

请勿把Cookie、Token、API Key、个人资料包、聊天原文或运行日志发进Issue。反馈问题时提供：系统与Harness版本、涉及的平台、手动还是自动、最小复现步骤，以及去掉个人信息的错误提示即可。
